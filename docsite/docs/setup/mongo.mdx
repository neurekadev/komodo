# MongoDB

[**MongoDB**](https://www.mongodb.com) is the recommended database for Komodo. It stores all resource configuration, user accounts, audit logs, and system state. Komodo Core communicates with it directly using the MongoDB driver.

## Quick Start

1. Create the installation directory and download the MongoDB template as `compose.yaml` and the environment file as `.env`:

```bash
mkdir -p komodo
cd komodo
curl -fsSL -o compose.yaml https://raw.githubusercontent.com/neurekadev/komodo/main/compose/mongo.compose.yaml
curl -fsSL -o .env https://raw.githubusercontent.com/neurekadev/komodo/main/compose/compose.env
```

2. Edit `.env`, replacing the example host, credentials, and secrets.
3. Review the resolved configuration and deploy:

```bash
docker compose config
docker compose up -d
```

Docker Compose discovers `compose.yaml` and `.env` automatically. The `.env` file sets `COMPOSE_PROJECT_NAME=komodo`, preserving the established `komodo_*` volume names.

:::warning Periphery host access
The template intentionally mounts Docker's named-volume root read/write into Periphery for host-visible workspaces and Docker-volume File Manager access. This makes Periphery Docker-host trusted. File Manager refuses to open `komodo_data` because it contains Periphery's private journal and credentials, but Server-level `FileManager` permission covers every other eligible named volume. Review the [File Manager trust boundary and permission scope](/docs/file-manager#containerized-periphery) before deploying.
:::
