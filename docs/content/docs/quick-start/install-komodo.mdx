---
title: Install Komodo
description: Start Core, MongoDB, and the local Periphery agent with Docker Compose.
---


Install Komodo on a Docker host to manage it from your browser. You need Docker Engine with the Compose plugin and an HTTPS reverse proxy that can reach port `9120`.

## Install

1. Create an installation directory with `mkdir -p komodo && cd komodo`.
2. Save the examples below as `compose.yaml` and `.env`.
3. Replace every `REPLACE_WITH_*` value. Set `KOMODO_HOST` to your public HTTPS address. Generate each password and secret independently with `openssl rand -hex 32`; keep the `${...}` credential references unchanged. Run `chmod 600 .env`.
4. Validate and start the services:

   ```bash
   docker compose -p komodo config --quiet
   docker compose -p komodo up -d
   docker compose -p komodo ps
   ```

5. Point your reverse proxy at Core on port `9120`, open `KOMODO_HOST`, and sign in with the administrator credentials from `.env`.
6. Open **Servers → Local** and confirm **OK**, then [deploy your first Stack](/quick-start/deploy-first-stack).

Periphery controls Docker and can read and write the host's Docker volumes. Grant access only to people you trust with that host. See [permissions](/administration/users-groups-permissions).

## compose.yaml

```yaml title="compose.yaml"
services:
  komodo:
    image: ghcr.io/neurekadev/komodo-core:${COMPOSE_KOMODO_IMAGE_TAG:-3}
    container_name: komodo
    depends_on: [komodo-mongo]
    env_file: [.env]
    networks:
      komodo:
        aliases: [core, komodo-core]
    ports:
      - "9120:9120"
    volumes:
      - data:/data
      - backups:/backups
    restart: unless-stopped
    init: true
    command: [core-compose]

  komodo-mongo:
    image: mongo:8
    container_name: komodo-mongo
    env_file: [.env]
    networks:
      komodo:
        aliases: [mongo, komodo-database]
    volumes:
      - mongo-data:/data/db
      - mongo-config:/data/configdb
    restart: unless-stopped
    command: --quiet --wiredTigerCacheSizeGB 0.25
    labels:
      komodo.skip: "true"

  komodo-periphery:
    image: ghcr.io/neurekadev/komodo-periphery:${COMPOSE_KOMODO_IMAGE_TAG:-3}
    container_name: komodo-periphery
    depends_on: [komodo]
    env_file: [.env]
    networks:
      komodo:
        aliases: [periphery]
    volumes:
      - data:/data
      - /var/run/docker.sock:/var/run/docker.sock
      - ${PERIPHERY_DOCKER_VOLUME_ROOT:-/var/lib/docker/volumes}:${PERIPHERY_DOCKER_VOLUME_ROOT:-/var/lib/docker/volumes}
      - /proc:/proc
    restart: unless-stopped
    init: true
    command: [periphery-compose]

networks:
  komodo:
    name: komodo

volumes:
  mongo-data:
  mongo-config:
  data:
  backups:
    labels:
      komodo.file-manager.excluded: "true"
```

## .env

Keep the database credential references below; [each container reads different variable names](/administration/container-deployment#database-credentials).

```dotenv title=".env"
KOMODO_HOST=https://REPLACE_WITH_HOST


KOMODO_DATABASE_USERNAME=komodo
KOMODO_DATABASE_PASSWORD=REPLACE_WITH_PASSWORD
MONGO_INITDB_ROOT_USERNAME=${KOMODO_DATABASE_USERNAME}
MONGO_INITDB_ROOT_PASSWORD=${KOMODO_DATABASE_PASSWORD}


KOMODO_INIT_ADMIN_USERNAME=admin
KOMODO_INIT_ADMIN_PASSWORD=REPLACE_WITH_PASSWORD
KOMODO_JWT_SECRET=REPLACE_WITH_SECRET
KOMODO_WEBHOOK_SECRET=REPLACE_WITH_SECRET
```

## If startup fails

Run `docker compose -p komodo logs --tail=200 komodo komodo-periphery komodo-mongo`. Check the host address and credentials; see [MongoDB troubleshooting](/administration/databases/mongodb#troubleshooting) if the database exits.

Keep `-p komodo` in later commands and retain the named volumes. They contain your database, identities, working files, and local backup repository. For image tags or a custom Docker root, see [Container Deployment](/administration/container-deployment).
