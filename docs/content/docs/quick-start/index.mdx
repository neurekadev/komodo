Komodo is a self-hosted web application for deploying and monitoring containers, Compose stacks, builds, and automated workflows.

The recommended installation starts MongoDB, Core, and a local Periphery agent together. The local agent lets Komodo manage the same Docker server immediately, so you do not need to install a second agent before deploying your first Stack.

<Callout title="Independent hard fork" type="warn">
  Komodo 3.0.0 and later has diverged from upstream Komodo. Start a fresh installation: migrations from upstream are not supported, and its data, configuration, agents, and clients must not be assumed compatible. Cherry-picked upstream fixes do not imply backward compatibility.
</Callout>

## What you need

- A Linux server with Docker Engine and the Docker Compose plugin.
- A DNS name or private-network address for Komodo Core.
- Permission to create directories, containers, networks, and named volumes.

## Complete the first deployment

1. [Install Komodo](/quick-start/install-komodo) with the recommended MongoDB Compose template.
2. Sign in and confirm the local Server reports **OK**.
3. [Deploy your first Stack](/quick-start/deploy-first-stack).

## Expected result

MongoDB, Core, and Periphery run in one Compose project. You can sign in, the local Server reports **OK**, and your first Stack shows its services as running.

## Optional next steps

- [Add another Server](/quick-start/add-another-server) when you want Komodo to manage a different Docker host.
- Use [FerretDB](/administration/databases/ferretdb) when MongoDB cannot run on the host.
- Review [Security and trust boundaries](/administration/security-and-trust) before exposing Core publicly or giving other users access.

Podman may work through a `podman`-to-`docker` alias, but Docker is the officially supported deployment platform.
