Komodo is a self-hosted web application for deploying and monitoring containers, Compose stacks, builds, and automated workflows across any number of servers.

This guide follows the shortest supported path from an empty Docker host to a managed stack.

## What you need

- A Linux server with a supported Docker Engine and the Docker Compose plugin.
- A DNS name or private-network address that can reach Komodo Core.
- Permission to create directories, containers, networks, and named volumes on the Core host.
- A second Docker server to manage, or permission to use the Core host as your first server.

Podman can work through a `podman` to `docker` alias, but Docker is the recommended path for a first installation.

## Complete the first deployment

1. [Install Core](/quick-start/install-core) with the MongoDB Compose template.
2. [Connect a server](/quick-start/connect-server) by installing the Periphery agent.
3. [Deploy your first stack](/quick-start/deploy-first-stack) from the Komodo interface.

## Expected result

You can sign in to Komodo, the connected server reports **OK**, and the first Stack shows its Compose services as running.

## If you need another path

- Use [FerretDB](/administration/databases/ferretdb) when the host cannot run current MongoDB images.
- Read [Core configuration](/administration/core-configuration) for OAuth/OIDC, private certificate authorities, and mounted configuration files.
- Review [Security and trust boundaries](/administration/security-and-trust) before exposing Core publicly or granting File Manager access.
