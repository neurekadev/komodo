---
title: FerretDB
description: Install Komodo with the PostgreSQL-backed FerretDB database option.
---


<Callout title="Information" type="info">

- If you setup Komodo using **Postgres** or **Sqlite** options prior to [**Komodo v1.18.0**](https://github.com/moghtech/komodo/releases/tag/v1.18.0), you are using **FerretDB v1**.
- Komodo now uses **FerretDB v2**. For existing users, [**upgrading requires a migration**](https://github.com/moghtech/komodo/blob/main/bin/cli/docs/copy-database.md#ferretdb-v2-update-guide).

</Callout>

[**FerretDB**](https://www.ferretdb.com) is a MongoDB-compatible database backed by [Postgres + DocumentDB extension](https://github.com/microsoft/documentdb).
It is a solid option with performance comparable to MongoDB, and can also be run on some systems which [do not support MongoDB](https://github.com/moghtech/komodo/issues/59).

1. Create the installation directory and download the FerretDB template as `compose.yaml` and the environment file as `.env`:

```bash
mkdir -p komodo
cd komodo
curl -fsSL -o compose.yaml https://raw.githubusercontent.com/neurekadev/komodo/main/compose/ferretdb.compose.yaml
curl -fsSL -o .env https://raw.githubusercontent.com/neurekadev/komodo/main/compose/compose.env
```

2. Edit `.env`, replacing the example host, credentials, and secrets.
3. Review the resolved configuration and deploy:

```bash
docker compose config
docker compose up -d
```

Docker Compose discovers `compose.yaml` and `.env` automatically. The `.env` file sets `COMPOSE_PROJECT_NAME=komodo`, preserving the established `komodo_*` volume names.

The expected result is healthy `komodo-postgres`, `komodo-ferretdb`, `komodo-core`, and `komodo-periphery` containers and a working sign-in page. If startup fails, inspect PostgreSQL and FerretDB logs first, verify their credentials match, and preserve both database volumes while troubleshooting.

[View the current FerretDB Compose template](https://github.com/neurekadev/komodo/blob/main/compose/ferretdb.compose.yaml) and [environment example](https://github.com/neurekadev/komodo/blob/main/compose/compose.env).

<Callout title="Periphery host access" type="warn">

The template intentionally mounts Docker's named-volume root read/write into Periphery for host-visible workspaces and Docker-volume File Manager access. This makes Periphery Docker-host trusted. File Manager refuses to open `komodo_data` because it contains Periphery's private journal and credentials, but Server-level `FileManager` permission covers every other eligible named volume. Review the [File Manager trust boundary and permission scope](/features/file-manager#containerized-periphery) before deploying.

</Callout>
