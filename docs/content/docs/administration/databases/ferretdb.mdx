---
title: FerretDB
description: Install Komodo with the PostgreSQL-backed FerretDB database option.
---


[**FerretDB**](https://www.ferretdb.com) is a MongoDB-compatible database backed by [Postgres + DocumentDB extension](https://github.com/microsoft/documentdb).
Use it when MongoDB cannot run on the host or PostgreSQL is an operational requirement.

The template pins FerretDB to major `2` and PostgreSQL/DocumentDB to major `17`. Use fresh volumes for a new fork installation; upstream Komodo migrations are not supported. Do not attach data from a different PostgreSQL major or FerretDB v1.

1. Create the installation directory and download the FerretDB template as `compose.yaml` and its matching environment file as `.env`:

```bash
mkdir -p komodo
cd komodo
curl -fsSL -o compose.yaml https://raw.githubusercontent.com/neurekadev/komodo/main/compose/ferretdb.compose.yaml
curl -fsSL -o .env https://raw.githubusercontent.com/neurekadev/komodo/main/compose/ferretdb.env
```

2. Edit `.env`, replacing every `REPLACE_WITH_*` value. Keep the `${...}` credential references unchanged. Use a URL-safe database password such as `openssl rand -hex 32`, because it is included in a connection URL. Protect `.env` with `chmod 600 .env`.
3. Review the resolved configuration and deploy:

```bash
docker compose -p komodo config
docker compose -p komodo up -d
```

Docker Compose discovers `compose.yaml` and `.env` automatically. Keep `-p komodo` in subsequent commands to preserve the `komodo_*` volume names. Configuration output includes secrets; do not share it publicly.

The expected result is running `komodo-postgres`, `komodo-ferretdb`, `komodo`, and `komodo-periphery` containers and a working sign-in page. Open **Servers**, select **Local**, and confirm **OK**. If startup fails, inspect PostgreSQL and FerretDB logs first, verify their credentials match, and preserve both database volumes while troubleshooting.

[View the current FerretDB Compose template](https://github.com/neurekadev/komodo/blob/main/compose/ferretdb.compose.yaml) and [environment example](https://github.com/neurekadev/komodo/blob/main/compose/ferretdb.env).

<Callout title="Periphery host access" type="warn">

The template intentionally mounts Docker's named-volume root read/write into Periphery for host-visible workspaces and Docker-volume File Manager access. This makes Periphery Docker-host trusted. File Manager refuses to open `komodo_data` because it contains Periphery's private journal and credentials, but Server-level `FileManager` permission covers every other eligible named volume. Review the [File Manager trust boundary and permission scope](/features/file-manager#containerized-periphery) before deploying.

</Callout>
