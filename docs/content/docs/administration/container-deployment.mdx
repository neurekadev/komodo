Start with the complete examples for [MongoDB](/quick-start/install-komodo), [FerretDB](/administration/databases/ferretdb), or [standalone Periphery](/quick-start/add-another-server). Apply these options when your host needs different defaults.

## Change an option

1. Back up `compose.yaml` and `.env`.
2. Add the required override to `.env` using the table below.
3. Run `docker compose -p komodo config --quiet`, then `docker compose -p komodo up -d` to recreate affected containers. A restart alone does not reload `.env`.
4. Confirm sign-in works and each Server reports **OK**. If it fails, restore the previous configuration and recreate the containers.

| Setting | Purpose |
| --- | --- |
| `COMPOSE_KOMODO_IMAGE_TAG` | Choose a specific release or `edge`; the default is `3`. Keep Core and Periphery on the same release. |
| `TZ` | Change the container timezone from UTC. Backups have their own timezone setting. |
| `KOMODO_FIRST_SERVER_NAME` | Choose the initial local Server name instead of `Local`. |
| `PERIPHERY_CONNECT_AS` | Connect Periphery to an existing Server by exact name. |
| `PERIPHERY_DOCKER_VOLUME_ROOT` | Use a different Docker volume directory. |

For registration, automatic account approval, and default permissions, see [Control registration and default access](/administration/users-groups-permissions#control-registration-and-default-access). Other optional variables, including login providers, UI settings, monitoring, and logging, are covered by the [environment variable references](/administration/core-configuration#find-an-environment-variable).

## Database credentials

Set `KOMODO_DATABASE_USERNAME` and `KOMODO_DATABASE_PASSWORD` once in the main installation's `.env` and keep the `${...}` references intact. The examples reuse the same account under the names each image requires:

| Variables | Consumer and purpose |
| --- | --- |
| `KOMODO_DATABASE_USERNAME`, `KOMODO_DATABASE_PASSWORD` | Core and the Komodo CLI authenticate to the database. |
| `MONGO_INITDB_ROOT_USERNAME`, `MONGO_INITDB_ROOT_PASSWORD` | The MongoDB image creates the initial database account. |
| `POSTGRES_USER`, `POSTGRES_PASSWORD` | The PostgreSQL/DocumentDB image creates the initial database account. |
| `FERRETDB_POSTGRESQL_URL` | FerretDB connects to PostgreSQL using that account. |

The native image variables are required wiring, not additional credentials to choose. Removing them breaks initialization or authentication in these examples. Changing `.env` does not change passwords already stored in MongoDB or PostgreSQL; update the database account separately before recreating containers with matching credentials.

## Custom Docker paths

Run `docker info --format '{{.DockerRootDir}}/volumes'` on the host and set `PERIPHERY_DOCKER_VOLUME_ROOT` to that absolute path. Keep it mounted read/write at the same path inside Periphery so Docker bind mounts and Volume File Manager operations work.

For rootless Docker, run `docker context inspect --format '{{.Endpoints.docker.Host}}'`. Replace the Compose bind source `/var/run/docker.sock` with the reported Unix socket path, without `unix://`; keep the container target `/var/run/docker.sock`.

## Persistent storage

Use `docker compose -p komodo ...` consistently and keep named volumes during maintenance. If you choose another project name, set `COMPOSE_PROJECT_NAME` to that name in `.env` and use it with `-p` too.

| Volume | Contents |
| --- | --- |
| `data` | Shared Core/Periphery identities, working files, cache, and `/data/core-secrets`. |
| `backups` | Local encrypted repositories. Core exposes them to workers through an authenticated endpoint. |
| Database volumes | MongoDB or PostgreSQL/FerretDB data. |

Core snapshots contain durable recovery secrets and database exports. Repository files and live database storage are excluded from workload backups. Keep Compose and `.env` separately for [Core recovery](/administration/recover-core).

Only Core's port `9120` is published by the main example. Database and local Periphery connections use the internal network; standalone Periphery connects outbound to Core.

Periphery's Docker socket and volume mounts give it host-level access. Use the focused standalone `.env` on additional hosts; the main installation's `.env` contains administrator and database secrets. Keep `chmod 600 .env`, and avoid sharing `docker compose config` output because it includes resolved secrets.

For mounted configuration files and private certificate authorities, see [Core and Periphery Configuration](/administration/core-configuration).
