---
title: Set Up Backups
description: Configure encrypted repositories and trusted backup workers.
---


Set up one encrypted repository and a shared schedule for Core, Stacks, and Docker volumes. You must be a Komodo administrator.

The bundled [Vykar release](https://github.com/borgbase/vykar/tree/v0.19.1) is marked as not ready for production backups. Test recovery and keep an independent backup alongside it.

Keep the repository address, access credentials, and encryption passphrase somewhere you can reach if Komodo is lost. A complete Core snapshot includes its recovery identity and backup settings; no separate `backup.key` is required. Keep your installation's Compose file and `.env` separately too.

## Configure backups

1. Open **Backups** and configure the **Primary** repository. **CoreLocal** uses `/backups/vykar` by default. Remote choices are S3, SFTP, and Vykar REST.
2. Enter an encryption passphrase. For remote storage, enter Core credentials and distinct worker credentials that allow backup reads and writes but deny deletion and maintenance.
3. Optionally add a **Mirror** on another host or storage service. Two directories on the same disk do not protect against disk loss.
4. Choose the schedule, timezone, protected categories, and complete snapshots to keep. Keep **Stop affected containers while backing up** enabled unless your applications provide their own consistency guarantees.
5. Under **Trusted backup workers**, select each source or restore-destination Server. Independently verify its address and Periphery public key, then select **Trust worker with repository access**.
6. Select **Save settings**. Restart Core after adding or changing a Core-local repository path.
7. Select **Initialize repositories**, then **Back up fleet now**. Check **Fleet status** and confirm a complete snapshot appears.

Trusted workers receive the shared repository passphrase and can decrypt all snapshots, including Core recovery secrets and saved repository credentials. Enroll only hosts you trust with that access. Separate worker credentials limit routine operations; they do not isolate secrets from a compromised trusted worker.

## Choose storage

| Backend | What to provide |
| --- | --- |
| CoreLocal | A persistent absolute path mounted into Core. Workers connect through Core's authenticated endpoint. |
| S3 | Bucket/prefix URL, region, and Core and worker access keys. **S3 soft delete** is off by default. |
| SFTP | Repository URL, complete private keys for Core and worker accounts, and the server's known-hosts entry. |
| REST | Repository URL and separate Core and worker tokens. Use HTTPS. |

The `backups` volume stores local repositories, not another copy of your application data. Komodo excludes repositories, live database storage, temporary backup files, and recovery journals from workload backups. Core recovery secrets live in the shared data volume under `/data/core-secrets` and enter backups through the Core export.

## If setup fails

Save changes before initializing or running a backup. If a worker is refused, check its enrollment and pinned public key. If a Core-local endpoint is unavailable, restart Core and verify the saved path is mounted persistently.
