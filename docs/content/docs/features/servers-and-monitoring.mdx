title: Servers and Monitoring
description: Connect Periphery containers and monitor Docker servers.

Every Docker server managed by Komodo runs a Periphery agent. Periphery receives commands from Core, operates Docker, and reports host and container information.

The recommended Komodo installation includes Periphery for the local host. To manage another host, follow [Add Another Server](/quick-start/add-another-server) for supported Docker Compose and `docker run` deployments.

## Check server health

1. Open **Servers**.
2. Select a Server.
3. Confirm its connection status is **OK**.
4. Review CPU, memory, disk, system process, and Docker resource information.

If a Server is disconnected, inspect its Periphery container logs and confirm that it can reach Core. For outbound connections, the Server name must match `PERIPHERY_CONNECT_AS` and the Server must not be configured for a Core-to-Periphery address.

## View Docker usage metrics

1. Open a connected **Server**.
2. Select **Images**, **Volumes**, or **Networks**.
3. Read the storage or traffic columns, or open an item for details.

Komodo shows an animated icon while Periphery completes the first background measurement. The result changes to the measured value or **Unavailable** with a reason. Image and volume storage usage refreshes every five minutes by default; set `docker_disk_usage_polling_rate` in Periphery configuration to change the interval.

If a storage metric remains unavailable, inspect Periphery logs and run `docker system df -v` on the host. Confirm that the command completes through the Docker socket used by Periphery. If the UI shows **The initial Docker disk usage measurement failed**, upgrade Periphery to a current image and recreate the container.

## Authentication and key rotation

Core and Periphery authenticate with automatically generated public/private key pairs:

1. An administrator creates an onboarding key under **Settings → Onboarding**.
2. Periphery uses that one-time secret to introduce its generated public key to Core.
3. Later connections authenticate with the persisted Core and Periphery keys.

Remove the onboarding key from the container environment after the first successful connection. The Periphery private key never leaves the server.

The repository's Compose and standalone `periphery-compose` examples persist keys beneath `/data/keys`:

| Component | Default path |
| --- | --- |
| Core private key | `/data/keys/core.key` |
| Periphery private key | `/data/keys/periphery.key` |
| Trusted Core public key | `/data/keys/core.pub` |

Each Server has an `auto_rotate_keys` setting, enabled by default, that controls whether it participates in the bulk `RotateAllServerKeys` operation. You can also rotate an individual Server's keys through the API or UI.

Onboarding keys can set expiration, default tags, a Server template, Builder creation, and whether they may repair the public key of an existing Server. Disable or delete a key when it is no longer needed.

## Container storage and Docker access

Periphery needs persistent storage for its identity, repositories, Stacks, builds, TLS files, and File Manager journal. The official Compose template stores these in the `komodo_data` volume and exposes host-visible aliases for Docker build contexts and relative Stack mounts.

The Docker named-volume root must be mounted at the same absolute path inside Periphery. Find the host path with:

```bash
docker info --format '{{.DockerRootDir}}/volumes'
```

Set `PERIPHERY_DOCKER_VOLUME_ROOT` when the result is not `/var/lib/docker/volumes`.

<Callout title="Docker host trust boundary" type="warn">
  The Docker socket and named-volume mount give Periphery host-level control. The volume-root mount is intentionally read/write for File Manager operations and host-visible Stack paths. Restrict Server and `FileManager` permissions to users trusted with the Docker host and its named-volume data.
</Callout>

## Advanced configuration

Environment variables are the simplest configuration method for containers. Every Periphery setting is also available in the [example TOML configuration](https://github.com/neurekadev/komodo/blob/main/config/periphery.config.toml).

To use a configuration file, mount a TOML, YAML, or JSON file beneath `/config`. Periphery loads files whose names match `*config*.*` by default. Multiple files are applied in order, with later values taking precedence.

Use `--merge-nested-config true` when override files should extend nested arrays and objects instead of replacing them. Pass additional command arguments through Compose's `command` field when needed.
