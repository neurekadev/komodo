---
title: Resource Sync
description: Declare Komodo resources in files and apply reviewed changes.
---

Use Resource Sync to manage resources from UI, host, or Git files. Komodo previews the changes before applying them. Use separate syncs with **Match Tags** when different projects should manage different resources.

## Apply a Resource Sync

### Prerequisites

- The declaration files contain no secrets.
- Git credentials are configured when the source repository is private.
- You have backed up or exported any existing resources the sync may replace or delete.

1. Open **Resource Syncs** and choose **New Resource Sync**.
2. Select UI, host file, or Git repository source and set the root file or directory.
3. Save and choose **Refresh** to compute the diff.
4. Review every create, update, delete, and deploy action.
5. Apply the sync only when the preview matches the intended state.

The expected result is a successful update whose applied actions match the reviewed diff. If the diff is unexpected, do not apply it; check match tags, source paths, duplicate resource names, and the selected branch.

## Commit to Syncs

If the Sync is pointing to just a single file, you can enable "Managed Mode" to allow Core to write the updates you made in UI _back to the file_.
This works no matter where the files are located, and will create a commit to your git repository for repo based files.

## Example declarations

Export an existing resource from Komodo for a starting configuration that matches your version. Keep secrets out of source files; use [Variables and Secrets](/features/variables-and-secrets).

### Stack

```toml
[[stack]]
name = "web"
tags = ["production"]
deploy = true
[stack.config]
server = "production"
repo = "myorg/stacks"
branch = "main"
file_paths = ["web/compose.yaml"]
env_file_path = "web/.env"
```

`deploy = true` lets the sync deploy the resource as part of the reviewed changes. Use `after = ["other-resource"]` to order dependent deployments.

### User Group

```toml
[[user_group]]
name = "operators"
users = ["alice", "bob"]
all.Stack = { level = "Read", specific = ["Logs"] }
permissions = [
  { target.type = "Stack", target.id = "web", level = "Execute" },
]
```

An `everyone = true` group grants its permissions to every user. Review [permission scope](/administration/users-groups-permissions) before applying user-group changes.
