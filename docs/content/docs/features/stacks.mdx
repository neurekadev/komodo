Komodo can deploy Docker Compose projects through the `Stack` resource.

## Deploy a Stack

### Prerequisites

- A connected Server reports **OK**.
- Your account can create a Stack on that Server.
- The Compose file and any referenced images, bind mounts, and networks are available to the target host.

1. Open **Stacks**, choose **New Stack**, enter a name, and select a Server.
2. Choose UI-managed files, host files, or a Git repository as the Compose source.
3. Add the Compose file paths and a distinct environment-file path.
4. Save, review the change preview, and choose **Deploy**.
5. Inspect the resulting services, logs, and update output.

The expected result is a **Running** Stack whose service state matches the Compose definition. If deployment fails, start with the first failed command in the update, run `docker compose config` against the same files on the host, and confirm repository and registry credentials.

If a project appears missing, run `docker compose ls --all` on the target host and check its configured project name.

## Advanced Configuration

```toml
[[stack]]
name = "my-stack"
[stack.config]
server = "server-prod"
run_directory = "/opt/stacks/my-stack"
file_paths = ["compose.yaml"]
env_file_path = ".env"
git_account = "my-user"
repo = "myorg/stacks"
environment = """
DB_HOST = db.example.com
LOG_LEVEL = info
"""
```

Use `project_name` when the Docker Compose project name differs from the Stack name. Keep the generated `env_file_path` distinct from every Compose file path so it cannot overwrite a Compose file.

Use [Automatic Updates](/features/automatic-updates) for image polling and [Variables and Secrets](/features/variables-and-secrets) for environment interpolation.

## Defining Compose Files

Stacks support three ways to provide compose files:

1. **Write in the UI** — Komodo writes the files to the host at deploy time.
2. **Files on the host** — Point to existing files on the server.
3. **Git repo** — Komodo clones the repo onto the host to deploy. Changes are tracked in git and you can use [webhooks](/features/webhooks) to auto-redeploy on push.

The Stack **Files** tab opens the directory containing the primary Compose file. UI-managed and host-file Stacks can be changed by users with Write and `FileManager` permission; repository-backed Stacks are read-only, and Swarm Stacks do not expose File Manager. See [File Manager](/features/file-manager) for supported operations and permissions.

## Importing Existing Projects

To import a running compose project, create a Stack in Komodo with access to the same compose files and attach the correct Server. Komodo matches projects by compose project name — if the running project name differs from the Stack name, set a custom `project_name` in the config. Run `docker compose ls` on the host to find existing project names.

## Deploying to a Swarm

A Stack can target a **Swarm** instead of a single Server to deploy via `docker stack deploy`. See [Swarm](/features/docker-swarm) for details.
